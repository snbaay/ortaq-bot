# Ortaq 2.0 functional specification

## Contract and vocabulary

One Telegram group is one household. Telegram user ID, not display name, identifies a person. The interface is Kazakh, informal `сен`, brief, and usually has at most two emoji per message. Static text and button captions live in `messages_kk.properties` via `MessageService`. Times are in `Asia/Almaty`. Money is ₸ with two decimal places. No Mini App, AI API, payment processing, card or banking credential collection, location tracking, or fridge inventory. A user-entered purchase is a record of what the user reported, not verified proof.

Buttons supplement the existing commands. Group activity stays in the group. `/start` and `/komek` in private chat explain the bot and show a safe menu of help; household writes and household data require the originating group. Private urgent notices go only to people who previously opened a private conversation with the bot and opted in. One user can belong to several households; every session and callback is bound to one group.

## Main menu and navigation

The group menu, opened by `/start` or a persistent `Мәзір` button on bot messages, has six rows: `🍲 Ас / Кезек`, `🛒 Өнімдер / Сатып алу`, `💰 Қаржы`, `⚡ Жылдам шақыру`, `📌 Басқа`, `⚙️ Баптаулар`. Do not use a global reply keyboard that fills normal chat. Inline keyboards are attached to bot messages. Menus are user bound where they reveal or mutate a draft. `⬅️ Артқа` returns one level, `✖️ Болдырмау` abandons the current draft, `🏠 Мәзір` returns to the main menu. Final destructive/financial actions offer `✅ Растау` and `✖️ Болдырмау`. An expired or already used button answers `Уақыты өтті. Мәзірді қайта аш.` and never mutates state. Unsupported private actions answer `Бұл әрекетті топта аш.`.

| --- | --- |
| `🍲 Ас / Кезек` | `📅 Бүгінгі кезек` (today and week), `🍲 Ас дайын` (actual cooks), `📖 Ас тарихы`, `🔄 Кезекті беру`, `⚙️ Кесте` (set/clear, confirmation) |

| `⚡ Жылдам шақыру` | `🍵 Шайға кел!`, `🍽️ Асқа кел!`, `🛒 Дүкенге барамын`, `🎮 Ойнайық!`, `🚨 Тез келіңдер`, `👋 Қонақ келеді` |

Each submenu displays an empty state and a back button. Lists are paged to stay below Telegram's message length and callback size limits. Errors leave the user at the same safe step with `Қайталау`, `⬅️ Артқа`, and `✖️ Болдырмау` where useful. Editing a shared message must never expose or overwrite a different user's draft.

## Commands and stabilization

All current commands remain recognized: `/start`, `/komek`, `/shygyn`, `/balans`, `/qaryz`, `/tolem`, `/oshiru`, `/tarih`, `/esep`, `/kezek`, `/kezek_qoyu`, `/kezek_tazalau`, `/otkizu`, `/dayyn`, `/tizim`, `/satyp`, `/jazba`, `/jazba_oshiru`, `/is`, `/ister`, `/songy`, `/merzim`, `/merzim_qosu`, `/merzim_oshiru`, `/kim`, `/tandau`, `/tiyn`. Preserve their syntax and valid existing records. `/shygyn amount description [mentions]` remains the explicit expense shortcut. Plain text such as `630 су` in a group is always ordinary conversation and creates no expense, even with BotFather privacy disabled. The V2 `/komek` and README remove old advice to enter a bare number. `/tolem` is retained as a syntax shortcut **to create a pending repayment request**, not an immediate settlement; the named recipient must confirm. `/dayyn` opens actual-cook selection; it does not credit the sender by default. `/satyp id` only marks an item on the to-buy list as bought; it does not create a purchase or expense. Existing settlement rows remain valid and are never rewritten. Existing `/oshiru` can soft-delete an owned old ledger row, subject to existing permissions; new confirmed repayments require the correction flow and recipient acknowledgment before reversal.

Group commands are allowed only to current registered members of that group. For schedule changes, all members may propose a change and see a confirmation; clearing the entire schedule requires confirmation by the initiator. For shared notes/deadlines, authors can delete their own records; existing legacy delete semantics must first be audited and migrated without changing old records. For urgent calls, the initiator chooses recipients; only selected current members can respond. Household settings use a designated manager: initially the first registered member, with an explicit transfer action and visible manager label; if no manager is yet assigned, existing members can elect one by a confirmation vote. This new role must not invalidate historical data or normal member commands. Manager changes household notification settings; individual members control private opt-in and presence.

## Products and purchase receipt

`➕ Сатып алуды жазу` shows `🕘 Соңғы өнімдер`, then categories. Categories are `🥕 Көкөніс` (қызанақ, қияр, картоп, пияз, сәбіз, орамжапырақ, сарымсақ), `🌾 Жарма / Ұн` (макарон, күріш, қарақұмық, ұн), `🥛 Сүт өнімдері` (сүт, айран, ірімшік, қаймақ), `🥚 Жұмыртқа`, `🍞 Нан`, `🥩 Ет / Тауық`, `🫖 Негізгілер` (май, қант, тұз, шай), `🥤 Сусын`, `🧽 Үйге керек` (тазалағыш, сабын, қағаз, қоқыс пакеті), and `✍️ Басқа өнім`. Show at most 8 product choices per page and page controls as needed. Catalog keys are stable; Kazakh labels are localized. Recent picks are the last five distinct products for this household, newest first, excluding canceled drafts. No stock counts or quantity-on-hand.

Product selection asks `Қызанақ қанша тұрды?` with a `ForceReply` prompt in the group. Accept only a reply by the same user to that prompt's message ID, in the same household, within 10 minutes. A command, unrelated message, another user's reply, or stale reply is never interpreted as a price. Price must be positive, at most 100,000,000.00 ₸, with at most two decimal digits; show a localized validation error and keep the prompt active. A custom name is 1–60 characters and uses the same reply binding. A basket is a 30-minute household/user draft; adding, editing, or removing a line updates its total using `BigDecimal`. Maximum 20 lines. The user can cancel the whole draft without DB purchase or expense. Photo receipt is optional: attach by reply to the basket's explicit photo prompt; save only Telegram `file_id`, file type/size and access metadata, never download it for V2. No OCR. A photo is not proof of purchase.

Basket buttons are `➕ Тағы өнім`, `✏️ Өңдеу` (select a line, then enter a new price), `🗑️ Алып тастау` (select a line, then confirm removal), `👥 Қатысушылар`, `🏠 Ортақ / 👤 Жеке`, `📷 Чек фотосы`, `✅ Растау`, `✖️ Болдырмау`. `⬅️ Артқа` from catalog returns to category and from a line editor returns to the basket without changing the line. Cancel asks `Себетті жоямыз ба?` with `Иә, жою` and `Жоқ, қалсын`. A missing item or total above 100,000,000.00 ₸ gives a specific error and retains the draft. Basket confirmation shows `Себет бос.` if all lines were removed.

Before confirmation, display line items, total, buyer, date/time, `Ортақ` (default) or `Жеке`, and participants. `👥 Қатысушылар` selects one or more current household members; payer is included in a shared split, consistent with `/shygyn`. `Жеке` makes no `Expense` or `ExpenseShare`, and does not affect balance or monthly shared report. `✅ Растау` creates one `Purchase` and all `PurchaseItem` rows; a shared basket creates exactly one linked `Expense` with amount equal to the basket total and shares summing exactly to that total. The expense description is a short localized receipt summary. A second confirm tap returns the existing receipt ID. No action is taken merely by selecting a catalog item. The receipt shows product, price, buyer, timestamp, status, participants if shared, optional photo, and linked expense ID if shared. Correcting a confirmed purchase uses an explicit cancel-and-reenter flow: buyer requests correction, which soft-deletes the linked expense and marks the purchase void atomically, then starts a new draft; a confirmed repayment is never auto-modified. Other members cannot void it.

The `📝 Алу керек` list remains independent. `/tizim` and `/satyp` keep their meanings. The store call can add to and view this list; marking bought there alone does not create a receipt. A receipt may optionally mark selected list entries bought in the same transaction, with no second accounting entry.

## Repayment confirmation

`💰 Қаржы → 🤝 Төлемді растау` starts with `Кімге төледің?` (household member buttons), then a prompt-bound amount reply, then a preview `Асанға 500 ₸ төледім деп жазасың ба?` with `✅ Сұрау жіберу` and `✖️ Болдырмау`. `/tolem Асан 500` takes the same route after parsing; it does not bypass confirmation or create a ledger entry. The recipient sees `Берік саған 500 ₸ төледім дейді. Растайсың ба?` with `✅ Растаймын`, `❌ Қабылдамаймын`. Only that recipient may decide; the request expires after 24 hours and then has no financial effect. A repeated acceptance returns the existing settlement ID. A rejection tells the sender without changing debt. `⬅️ Артқа` before sending returns to amount/recipient selection; after sending, cancellation is permitted only while pending and by the sender. For a mistaken confirmed repayment, the sender or recipient opens `✏️ Түзету`, states a short reason and sends a reversal request to the other party; only mutual confirmation soft-deletes the linked settlement once, leaving an audit row. The command syntax remains familiar but the success text says `Растау сұрауы жіберілді`, never `Қарыз жабылды` until recipient acceptance.

## Cooking

The fixed weekly schedule and date-specific swaps remain. `📅 Бүгінгі кезек` shows effective cooks after swaps, the seven-day schedule, and day-off state. Around 18:30, remind only today's effective cooks if no ready event exists; manager can enable/disable and adjust time 17:00–21:00. `🍲 Ас дайын` or `/dayyn` opens today's effective cooks preselected as **suggestions**, allows adding/removing any current household member, and allows an optional note. The confirmer is recorded separately; the button click never credits that person automatically. Confirmation creates one `CookingEvent` for household/date/occasion, snapshots scheduled cooks and actual cooks, confirms at `Asia/Almaty`, stops future reminders, and offers `🍽️ Асқа кел!`. Empty actual-cook selection is rejected. If no schedule exists, actual cooks must be selected manually. A duplicate ready click shows the existing event. `✏️ Түзету` requires the original confirmer or a manager, shows prior and proposed cook lists, and records editor/time/reason; history displays both scheduled and actual cooks and corrections. A new occasion on the same date requires an explicit manager-created occasion number, preventing accidental duplicate ready events.

## Quick calls and social events

Each action creates one group announcement with response buttons; the initiator can close it. Tea and food: `🙋 Келемін`, `⏱ 5 минутта`, `🙅 Келмеймін`; food also offers `🍲 Маған қалдырыңдар`. Responses are one row per user/event and a new response replaces the old one. Store: `📝 Не керек?` opens the to-buy input, `📋 Тізім` shows current items, `✅ Жабу` closes the call; after close, replies and adds through that call are rejected while `/tizim` remains available. Play chooses `🎮 FIFA`, `🎬 Кино`, `🚶 Серуен`, or `✍️ Басқа`; custom activity uses an explicit reply prompt. Responses: `🙋 Қосыламын` and `🙅 Бұл жолы жоқ`. Urgent: choose one or more current members or `Барлығы`, preview mentions, and confirm. A group mention is the default; optional private notification only for opted-in users with a known private chat. No voice call is possible. Limit each initiator to one urgent call per 30 minutes and each household to four per day; quiet hours suppress private sends unless the manager enabled an explicit urgent exception. Guests: choose approximate arrival (`Қазір`, `1 сағатта`, `Кешке`, or custom time), optional short note, then announce; responses `👍 Түсіндім` and `💬 Талқылау` (the latter prompts an ordinary group reply, not a stored surveillance thread). General calls expire after two hours, store calls after four hours, urgent after 30 minutes; close/expire disables buttons. Rate-limit other calls to three per user per 30 minutes. Suppress repeated announcement sends from duplicate updates.

Before any call is posted, `⬅️ Артқа` returns to its choice screen and `✖️ Болдырмау` discards it without an announcement. The final preview uses `✅ Жіберу`. After posting, only the initiator may press `✅ Жабу`; participants see `Шақыру аяқталды.` on an old button. An invalid custom activity or guest time keeps the prompt active with an example. If no selected urgent recipient has a Telegram username, show display names in the group and explain that direct mentions may not notify them; never imply a voice call occurred.

## Other household use

Shopping list shows open items and ownership, supports adding, bought marking, and clear empty state. Chores show recent actions and `/songy` results with safe empty states. Notes show author and creation time. Deadlines show next occurrence and retain 1/3/0-day reminders. `/kim`, `/tandau`, `/tiyn` retain current behavior. The monthly report excludes settlements and personal purchases, includes linked shared purchases exactly once, and keeps historic expenses. Presence is voluntary `🏠 Үйдемін` / `🚶 Сырттамын`, with explicit clear and automatic expiry after 12 hours, no GPS, no history beyond the active row. Dinner attendance poll asks `Бүгін кешке ас ішесің бе?` with `Иә`, `Жоқ`, `Әлі білмеймін`; one active poll per household/date, response update allowed, expires at configured dinner time, and cannot imply who cooked. Optional night reminder around 23:15 is off by default. Manager sets household notification switches and quiet hours (default 22:00–08:00); no routine notification during quiet hours, and missed reminders are skipped rather than blasted later. Every scheduled delivery has a durable event key and status so a restart does not duplicate it.

## Failure and authorization behavior

Every callback rechecks Telegram sender ID, group chat ID, household membership, target row household, event status, session owner, version, and action permission in the service transaction. Never trust callback payload names, amounts, or role claims. Reject a button forwarded to another chat and a removed/nonmember user. A response update is idempotent, including repeat taps and duplicate Telegram updates. If Telegram delivery fails after a DB commit, retain a send state for a bounded retry; users can see a safe pending status without a second ledger write. When a prompt expires, reply `Бұл қадамның уақыты өтті. Қайта баста.`. For invalid money, say `Соманы дұрыс жаз: 1250 немесе 1250,50.`. For no records, say `Әзірге ештеңе жоқ.`. For denied actions, say `Бұл әрекетке рұқсатың жоқ.`. Never expose another household's data even if its numeric ID is supplied.

Committed V2 scope is exactly the flows above and the tasks in `PLAN_V2.md`. Future backlog: OCR, stock inventory, Mini App, AI assistant, language switching, CSV export, webhook, multi-instance polling, and actual payment rails. They are not dependencies of V2.
